# Web出退勤システム

30人程度の社員が共有端末やタブレットから簡単に打刻できる、静的Webアプリのサンプルです。フロント画面で社員を選び、出勤または退勤ボタンを押すと、日本時間（JST）の日時で打刻します。Google Apps Scriptを経由してGoogleスプレッドシートへログを追記できます。

## 主な機能

- 日本時間で自動更新される大きな日付・デジタル時計
- 10人ずつ3ブロックに分けた社員選択ボタン
- 出勤・退勤だけの大きな打刻ボタン
- 打刻時刻を画面更新なしで取得
- 別画面の管理画面（`#admin`）と簡易ログイン認証
- 管理画面から以下を設定
  - Apps Script WebアプリURL
  - GoogleスプレッドシートID
  - 任意のAPI共有シークレット
  - 管理パスワード
  - グループ名・社員名の追加、変更、削除
- Google連携未設定時や通信失敗時のローカルバックアップ保存

## ファイル構成

```text
.
├── index.html                 # 画面のHTML
├── styles.css                 # UIスタイル
├── app.js                     # 時計、打刻、管理画面、設定保存処理
└── google-apps-script/
    └── Code.gs                # Google Apps Script側の受信・Sheets追記処理
```

## ローカルでの起動

静的ファイルだけで動作します。任意のHTTPサーバーで配信してください。

```bash
python3 -m http.server 8080
```

ブラウザで `http://localhost:8080` を開きます。

## 初期管理ログイン

1. 画面右上の「管理画面」を押します。
2. 初期パスワード `admin1234` でログインします。
3. 本番運用前に必ず管理パスワードを変更してください。

> 注意: このサンプルの管理認証と設定値はブラウザの `localStorage` / `sessionStorage` に保存されます。社外公開や厳格な認証が必要な本番環境では、サーバー側認証・権限管理へ置き換えてください。

## Googleスプレッドシート連携手順

1. Googleドライブで集計先のスプレッドシートを作成します。
2. スプレッドシートURLからIDを控えます。
   - 例: `https://docs.google.com/spreadsheets/d/<ここがID>/edit`
3. Google Apps Scriptプロジェクトを作成し、`google-apps-script/Code.gs` の内容を貼り付けます。
4. 任意でApps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」に以下を追加します。
   - キー: `ATTENDANCE_API_SECRET`
   - 値: 任意の共有シークレット
5. Apps ScriptをWebアプリとしてデプロイします。
   - 実行ユーザー: 自分
   - アクセスできるユーザー: 運用方針に合わせて選択
6. WebアプリURLを控えます。
7. 本アプリの管理画面で、WebアプリURL、スプレッドシートID、共有シークレットを保存します。

## スプレッドシートに作成される列

Apps Scriptは `出退勤ログ` シートを自動作成し、以下の列で追記します。

| 列 | 内容 |
| --- | --- |
| タイムスタンプ | `YYYY-MM-DD HH:mm:ss` 形式のJST時刻 |
| 日付 | 打刻日 |
| 時刻 | 打刻時刻 |
| 種別 | 出勤または退勤 |
| 社員ID | ブラウザ設定内の社員ID |
| 社員名 | 管理画面で設定した社員名 |
| グループID | ブラウザ設定内のグループID |
| グループ名 | 管理画面で設定したグループ名 |
| タイムゾーン | `Asia/Tokyo` |
| ユーザーエージェント | 打刻端末のブラウザ情報 |

## 運用上の補足

- 共有端末で利用する場合、管理画面は使用後にログアウトしてください。
- CORS制約を避けるため、フロントからApps Scriptへの送信は `no-cors` で行っています。そのためブラウザ側ではApps Scriptの詳細なレスポンス本文は確認できません。
- 打刻は送信前に最大300件までローカルバックアップされます。Google連携が未設定でも、ブラウザ内には直近の打刻が残ります。
- 複数端末で社員設定を共有したい場合は、設定管理もサーバー側またはスプレッドシート側に移す拡張を推奨します。
